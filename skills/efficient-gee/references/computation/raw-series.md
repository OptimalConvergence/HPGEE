# Full-support HLS30 / S1 scene graphs

These local APIs build raw observation sequences separately from RF features, composites and the older observation-package contract. Import a pinned HPGEE version whose `hpgee.transfer` package contains `raw_download` and `raw_delivery`; the canonical maintenance checkout is not a published release.

## Source and grid contract

Enumerate the original collections completely, verify native footprints, then freeze source IDs/time, metadata scales, band grids, UTC half-open window and exclusions. Subsequent pixel requests use those source IDs directly. Listing metadata has no per-request workload tag and its wall time is not EECU. A failed or capped query is not a complete empty inventory.

`raw_download.raw_image(scene, pixel_grid, profile)` supports:

| Profile | Transport order / units | Support |
|---|---|---|
| `hls` | blue, green, red, nir, swir1, swir2, Fmask, source_valid_bits | L30/S30 six-band reflectance, all observations, original band validity and QA validity |
| `hls-int16` | Same eight bands; six reflectance bands are signed Int16 codes `round(value * 10000)`, followed by Fmask and source validity | Explicit opt-in encoding of the same HLS observations and masks as `hls` |
| `s1-10` | VV_power, VH_power, source_valid_bits, valid_fraction | IW VV/VH GRD sigma0 converted from dB to linear power on the source grid |
| `s1-30` | Same four bands | Common-valid area-weighted linear power on the frozen HLS grid |

Historical `hls` and both S1 profiles use Float32 transport. `hls-int16` is a separate opt-in profile and recipe: multiply each source reflectance value by 10,000, round, then transport six signed Int16 codes plus Fmask and `source_valid_bits`; decode reflectance as `code * 0.0001 + 0`. Fmask and validity are stored separately as uint8 QA. The validity bits remain authoritative when the Int16 data file uses zero as invalid fill, so valid reflectance code zero remains valid. Transport bit 7 marks any reflectance overflow outside `[-32768, 32767]`; the publisher rejects the atom rather than accepting a wrapped or clipped value. `make_unit(..., "hls-int16")` passes a two-byte item size to `pack_limit`; the extra one-byte-per-element mask allowance is a conservative planning margin, not a measured Int16 wire-size claim. The profile identity freezes dtype, scale, offset, QA bands and overflow bit. Its recipe is `raw-hls-int16-scale1e4-v1`; historical `hls`, `s1-10` and `s1-30` identities and Float32 defaults remain unchanged, and Float32 receipts must not be relabeled or reused as Int16. HLS has eight transport bands per scene and S1 has four; S1 delivery stores Float32 `[VV_power, VH_power, valid_fraction]` plus separate uint8 `[source_valid_bits]`, and QA always counts toward the transport payload and request budget. The raw contract omits the older observation package's `clear` and `angle` bands; callbacks for those packages are not interchangeable.

`make_unit(scenes, pixel_grid, profile)` freezes source/grid/recipe identity, temporal band names and dtype-aware logical payload bytes. `unit_image(unit)` assembles the expression. `pixel_grid` uses computePixels CRS, dimensions and affineTransform fields. `native_window` computes an integer native-pixel envelope of the source-grid/tile intersection. Preserve relative orbit, pass and acquisition UTC in the source ledger rather than collapsing different geometries into one series identity. Recipe identity is profile-specific: `s1-30` uses `raw-s1-30-value-support-v2`; `hls-int16` uses `raw-hls-int16-scale1e4-v1`; historical HLS, `s1-10` use `raw-full-support-v1`. Rebuild units under the selected recipe and reject cached units or receipts whose profile/recipe/encoding differs; do not relabel Float32 HLS receipts as Int16 or old `s1-30` receipts as v2.

For raw S1 30m, carry a native-grid value of one on common VV/VH-valid support, fill unsupported cells with zero, then aggregate the support and each linear-power value to the frozen HLS target grid with the same overlap weights. The numerator is the sum of power times effective overlap weight over common valid support; division by `valid_fraction` gives the common-valid area mean. `valid_fraction` is the share of the whole target-cell area with common valid support: values between zero and one are partial support, and one is full support. A zero fraction and `source_valid_bits=0` mean no common valid contribution; that pair alone cannot tell known outside-footprint area from missing common-valid source data. Use the frozen source footprint to identify and record geometrically outside portions separately; do not infer outside support from the fraction alone. A missing file, failed transfer, or absent receipt remains unknown, not a zero fraction or source-empty observation. The v2 aggregate QA bits are 0 or 3: 3 means both target power values have common support, and 0 means neither does. These bits do not encode native subpixel detail. Aggregate power before logarithms. Do not average dB or convert a GRD dB band to logarithms again. For bounded `s1-30` acceptance, preselect saved-pixel strata covering observed support, partial/empty support, target-grid edges, outside-footprint areas and relevant orbit/pass/source groups, then compare both powers, fraction and QA at each selected target pixel against an independent oracle from saved native values/masks with the same area weights. A passed stratified sample supports only bounded acceptance of the tested cohort/strata; any claim of numerical agreement over the full saved cohort requires the oracle at every target pixel. Keep full-grid CRS/affine/dimensions, file-hash, dtype and QA/publisher checks for every atom regardless of numerical-oracle sample size.

This recipe change applies only to the raw `s1-30` path. It does not change or validate general observation packages, RF features/defaults, composites or the separate native `s1-10` path.

The [GRD source](https://developers.google.com/earth-engine/guides/sentinel1) is already calibrated and geometrically terrain-corrected; it is not unprocessed SAR/SLC. Extra speckle filters change the product and require separate quality evidence. Ten-to-thirty metre aggregation reduces equal-area sample count by about nine, not necessarily nine independent looks or nine times the actual request bytes when native and target envelopes differ.

HLS source scale properties do not authorize applying a scale twice. Confirm the actual EE pixel representation and saved values before proposing or selecting an integer encoding. For `hls-int16`, the frozen scale/offset, rounding, nodata and reconstruction are specifically `round(value * 10000)`, scale `0.0001`, offset `0`; apply no additional source scale. Retain valid zeroes, negative reflectance, outliers and every band mask. The QA sidecar distinguishes valid zero codes from invalid fill, and the overflow sentinel causes rejection rather than clipping. A complete-cohort lossless claim requires reconstruction of every valid value in the claimed accepted cohort, with per-band counts/ranges/errors and unchanged independent QA. A bounded subset supports only a bounded claim. Full-cohort local encoding evidence does not establish online transport or archive-wide support. S1 power requires a separate error/encoding analysis. Native QA and business cloud/snow rules are separate; an optional tile-level exclusion changes the full-observation product and needs its own source-valid denominator, threshold and measured cost/quality benefit. Reuse saved QA rather than launch another EE scan when it answers that comparison.

For HLS tile-mask statistics, evaluate over an explicit full target-grid extent and define the statistic's semantic denominator separately (for example, all target cells versus cells with valid Fmask). Default `unmask(0)` retains the source footprint and can omit target-grid edge cells from the reducer even when CRS and affine match the published grid. In the verified three-variant comparison, `unmask(0, sameFootprint=False)` (equivalently `unmask(0, False)`) produced per-class QA counts that matched the saved QA exactly. Check both the evaluation extent and denominator semantics against saved QA/support before applying a clear/cloud threshold; do not assume a metadata threshold uses the same denominator.

## Delivery and partition consistency

Use `DownloadEngine.download_frozen_blocks` with `raw_delivery.publish`/`verified`, preserving the exact source/grid/unit contract. The publisher validates dtype, CRS/affine, edge dimensions, source-valid values, Fmask and common-support fraction before immutable hashed receipts. It keeps source-empty blocks rather than inventing valid observations. Successful transport is not event-level scientific acceptance.

Historical HLS WKT can name the WGS84 datum differently from EE's emitted EPSG UTM label. `same_hls_grid` permits the specific identical WGS84 UTM zone/hemisphere, metric ellipsoid, affine and dimensions; it is not general permission to substitute arbitrary CRSs. S1 30m inherits that HLS target grid. S1 native-grid checks retain its original projection.

Current receipt subdivision starts at each request's origin, with 512-pixel pieces. Cross-size production reuse needs the same underlying 512-pixel lattice or an explicit reconciliation of fragments. Keep arbitrary-size ablations in separate outputs until their full-region reconstruction has passed gap/overlap and pixel comparisons. The request payload limit includes QA and all temporal slices, not just six optical or two radar science bands.

## Verification and scope

Freeze and validate source lists before performance work. Test saved pixels, masks/QA, edges, units and interrupted replay. For spatial controls, compare the same fixed source region with every edge block retained; report repeated transfers and cache effects separately. Record logical, observed, HTTP and saved bytes separately. A user-specified 30m analysis grid does not add native spatial information.

Independent complete-cohort atom acceptance and full-cohort HLS integer reconstruction have been exercised for a frozen source series. This establishes that cohort and recipe, not optimal concurrency, global mean observation density or archive-wide science qualification. Keep current experiments, exact measurements and failures in the caller's project. These raw APIs leave existing RF/composite defaults unchanged and do not grant new execution or export authorization.

Choose bounded performance configurations from repeated equal source-region comparisons using total matched bytes divided by total elapsed time, including slow trials. Retain full-grid edge/request-count sensitivity when the finite controls have different request partitions. EE cache state is uncontrolled; queue grouping has no presumed benefit. Larger blocks or integer payloads proven on a few sources at low concurrency remain scoped controls until actual concurrency, saved-pixel QA and recovery pass. HTTP attempt elapsed time includes remote computation and body transfer, so it is not pure network latency.

Freeze a byte and request budget by source and grid, then enforce both per-source limits and their whole-study sum using the actual dtype, band count and edge shape. Preserve source attribution for each request and outcome; a flat task-count cap is not a byte cap. Feed eligible source-specific tasks through the same bounded worker pool or interleave them in a prespecified order. Do not add a serial barrier after each source that leaves workers idle or changes effective concurrency between arms. A transport observer `started` event occurs before `session.request` and its local send-budget guard, so it records an observed transport attempt but does not by itself confirm HTTP dispatch. Count confirmed dispatches from dispatch-reservation or lower-level send instrumentation; an explicit local pre-send rejection such as `BudgetExceeded` with no dispatch reservation is a local attempt outcome, zero confirmed HTTP dispatches and zero remote compute. If dispatch evidence is absent without a known pre-send rejection, keep send status unknown. If dispatch is recorded but its matching finish event is absent, retain the confirmed dispatch but leave response, body and cost unknown. Engine task `attempts`/`retries` are not a substitute for dispatch evidence. Historical observer start/finish rows remain unchanged and must not be reinterpreted as confirmed sends without dispatch evidence. Keep logical, observed, server-charged, HTTP-response and stored bytes separate from wall time and reported EECU. HTTP response-body byte counts are decoded body bytes, not TLS or interface wire bytes. Compression ratios cannot scale time or EECU. A repaired phase retains its original successes, time, failed/unknown HTTP attempts and cost before adding the repair. Reconcile delayed Monitoring from the actual final request without rerunning pixels; missing cost remains unknown. Freeze transitive entrypoint helpers as well as graph/library code and exercise the queued offline entrypoint before submission.

## Empirical masked-payload guard

The current Float32 raw planner keeps a 40 MiB value-plane target and also guards the 48 MiB API boundary using an observed extra byte per requested band/pixel. A masked HLS request has reported a server charge equal to `width * height * bands * 5`, although the Float32 value planes alone use 4 bytes. This overhead is an empirical conservative guard, not a universal mask-accounting guarantee in the REST documentation. Keep logical values, server charge, HTTP bodies and stored files separate. Recheck dtype plus all temporal/QA bands before increasing request dimensions; scaled Int16 does not automatically make a 1600² optical request feasible.

Point MGRS latitude-band labels are not a substitute for actual overlapping HLS/Sentinel tile identities. Freeze asset tile names and source footprints from the catalogue; centroid grid/window unions are explicitly conditional sizing proxies.


## Validation cost versus production transfer cost

Keep reference-raster reads and scientific oracle comparisons in a separately timed validation phase. After accepting a frozen source/grid/recipe cohort, reuse its compact validation evidence in later transfer experiments instead of re-reading every raster before each run. Production transfers can omit that repeated reference phase; deferred local hash or pixel QA must retain its own pending/passed status rather than inflate download time.

Additional EECU allowance does not establish lower response latency or a larger interactive request quota. Compare compute graphs with identical saved-value/support contracts and measured response timing. A raw-power source change, temporal packing or provider-native path is a separately versioned candidate until membership, masks, units and grid are compared; do not assume a faster source is scientifically equivalent.
