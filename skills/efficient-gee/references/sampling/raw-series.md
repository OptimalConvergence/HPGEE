# Original-scene sequence transfer

Use a pinned HPGEE snapshot with the shared `hpgee.transfer` and `hpgee.accounting` capabilities for an authorized raw-series experiment. The computation library builds frozen source/grid units; `DownloadEngine.download_frozen_blocks` owns HTTP, retries and writers. This mode does not perform catalog selection or cloud filtering. It is separate from RF/product/observation-package callbacks; a raw S1 30m recipe change does not validate those other branches.

## Identity, acceptance and reuse

Freeze asset IDs, acquisition UTC, collection/version, source scale/offset, native support, target CRS/affine/dimensions, ordered bands and processing recipe before transferring. Fully paginate discovery first. Metadata query time is not EECU; source IDs alone do not prove archive completeness.

`raw_download.make_unit(scenes, pixel_grid, profile)` creates units for `hls`, `hls-int16`, `s1-10` or `s1-30`; `unit_image(unit)` builds the lazy expression. Historical `hls` and S1 transport remain Float32 (eight HLS bands or four S1 bands per scene). The explicit `hls-int16` profile sends six signed Int16 reflectance codes `round(value * 10000)` plus Fmask and source-validity QA; decode with scale `0.0001`, offset `0`. Its recipe is `raw-hls-int16-scale1e4-v1`, distinct from historical HLS recipe `raw-full-support-v1`; its identity includes dtype, scale, offset, QA bands and overflow flag bit 7. `make_unit` passes itemsize 2 to `pack_limit`; the additional one-byte-per-element mask allowance is a planning margin, not measured Int16 wire size. `raw_delivery.publish` checks saved grid, dtype, validity and values, then splits science and QA into separately hashed files/receipts. For Int16, the uint8 QA sidecar is authoritative even when a valid reflectance value and invalid fill both have code zero; bit 7 marks overflow and causes publisher rejection, not clipping. Historical `hls`, `s1-10` and `s1-30` identities and Float32 defaults remain unchanged. Do not reuse/relabel Float32 HLS units/receipts as Int16. S1 data files contain Float32 `[VV_power, VH_power, valid_fraction]`; the companion QA file contains uint8 `[source_valid_bits]`. QA is still part of the request payload and byte budget. `s1-30` units use recipe identity `raw-s1-30-value-support-v2`; rebuild under the current recipe and reject old-recipe units/receipts during verification rather than reusing or relabeling them. The publisher preserves source-empty blocks as source-empty, rather than interpreting them as clear or unburned. A source-empty block can be valid transport evidence; it is not observed-data throughput.

For `s1-30`, support is carried as native-grid values before reduction: common VV/VH-valid cells contribute one and unsupported cells contribute zero. `valid_fraction` is the proportion of each whole target-cell area with common valid support. Fractions between zero and one are partial; zero with `source_valid_bits=0` means no common valid contribution, but does not by itself distinguish known outside-footprint area from missing valid source data. Use the frozen source footprint to identify and record geometrically outside portions separately; do not infer outside support from the fraction alone. Missing files, failed transfers and absent receipts stay unknown; they are not zero-support or source-empty pixels. The v2 aggregate QA bits are 0 or 3: 3 means both target power values have common support, and 0 means neither does; they do not encode native subpixel detail. For bounded acceptance, preselect saved-pixel strata covering observed, partial and empty support, target-grid edges, outside-footprint areas and relevant orbit/pass/source groups; compare both powers, fraction and QA at every selected pixel against an independent oracle from saved native source values/masks. This supports only the tested cohort/strata. A numerical claim for every saved target pixel requires oracle comparison at every pixel. Keep complete atom-level grid, hash, dtype and publisher QA validation in all cases; bounded numeric-oracle sampling does not waive those checks.

Use the existing engine's `image_builder`, `bands`, `grid_builder`, `verified` and `publish` callbacks, with a bounded independent writer count. `verified` must establish source/grid/recipe identity and file hashes before a skip. Keep accepted IDs in memory after one recovery scan rather than repeatedly hashing all TIFFs during each parameter trial. Hot engine SQLite remains on allocated local storage.

`raw_delivery.atoms` subdivides each request from that request's origin in steps of 512 pixels. Cross-size reuse therefore requires compatible origins and boundaries. A 1024 or 1536 request can preserve the same 512-pixel lattice; an arbitrarily shifted 1120 request generally does not. Do not label overlapping physical pixels with different receipt identities as cache hits. Reconcile intersections onto one fixed lattice before production reuse, or keep such controls in separate study outputs and charge their repeated transfers explicitly.

Temporal packing requires the same output grid and preserves each scene's identity. Native S1 grids often differ, so native-grid temporal packing can be inapplicable even when scenes overlap geographically. Calculate payload from every transported band, dtype, edge shape and time slice. Historical HLS/S1 profiles use itemsize 4 in `pack_limit`; the explicit `hls-int16` profile passes itemsize 2 and keeps the one-byte-per-element mask allowance as a conservative planning margin. The Float32 40 MiB value-plane planning envelope sits under the service's [48 MB uncompressed limit](https://developers.google.com/earth-engine/reference/rest/v1/projects.image/computePixels); Int16 sizing is an explicit candidate implementation path, not an empirical wire-byte guarantee. Do not infer transport savings from local compressed storage ratios.

## Run-scoped measurement

`hpgee.accounting.run.UsageRun(directory, project=..., tag_prefix=..., credentials=...)` persists its original start. Reopening the same directory requires the same project/prefix. Give distinct studies distinct directories and prefixes. Use the same EE credential object for computation and Cloud Monitoring:

```python
credentials = ee.data.get_persistent_credentials()
usage = UsageRun(run_dir, project=project, tag_prefix=prefix, credentials=credentials)
ee = initialize_earth_engine(
    AuthConfig(project=project), pool_size=max_workers,
    observer=usage.observe_http, credentials=credentials,
)
usage.start()
try:
    # Download through the existing engine with explicit per-run request tags.
    pass
finally:
    usage.stop()
```

Do not change a global workload tag from concurrent workers. The HTTP observer's `started` event is emitted before `session.request` and its local send-budget guard; it records a transport attempt, not a confirmed HTTP dispatch. Count confirmed dispatches using dispatch-reservation or lower-level send instrumentation. Keep explicit local pre-send rejections (for example, `BudgetExceeded` with no dispatch reservation) separate: they are local attempts with zero confirmed HTTP dispatches and zero remote compute. Without dispatch evidence and without a known local rejection, send status remains unknown. With dispatch evidence but no matching finish event, retain the dispatch and mark response, body and cost unknown. Finished observer events carry status, response-body bytes and timings, but historical observer start/finish rows alone do not establish that a dispatch passed the local guard. Engine task `attempts`/`retries` are task-level outcomes and do not replace dispatch evidence. Response-body bytes are decoded HTTP payload bytes, not TLS/interface wire bytes. Observed request elapsed time includes service computation, transport and body consumption; it is not pure network latency. Retain observer attempts, confirmed dispatches, local pre-send rejections and unresolved outcomes separately. Failed or unreported EE computation must not become zero EECU.

Monitoring uses the persisted interval, full pagination, project/tag validation and point deduplication. A rolling 30-minute window cannot measure a longer run. Report completed and in-progress views separately; they overlap. Their maximum is only an approximate budget indicator. Reconcile delayed telemetry without rerunning pixel requests. Anchor the follow-up interval to the actual final HTTP attempt, including repair/retry requests, rather than a nominal controller end. If monitoring fails after a successful snapshot, retain the prior reported amount with its timestamp and flag it stale; a missing tag stays unknown. The wrapper's default polling interval is 120 seconds, not a universal accuracy guarantee.

`ResourceMonitor` requires psutil and measures per-process CPU time within its process tree, RSS, logical I/O and local scratch. A separately running proxy is outside that process tree, so its CPU and RSS are excluded unless measured separately. Node-network counters include other jobs and proxy traffic; they do not prove one process's bandwidth. Count monitoring HTTP calls/time separately. See [official monitoring guidance](https://developers.google.com/earth-engine/guides/monitoring_usage).

## Comparable studies and evidence limits

Compare equal source-pixel work and report observed support alongside logical bytes; equal request counts can contain very different amounts of valid data. Freeze per-source as well as total byte/request caps from the actual dtype, bands and edge shapes, and retain source identity in every task outcome. Run eligible tasks through the same bounded pool or interleave sources in a prespecified order; avoid serial per-source barriers that leave workers idle and make the compared arms use different effective concurrency. Reverse order across comparable sources and distinguish deliberate warm repeats from first transfers. EE cache state is not user-controlled, and a grouped queue has no presumed cache advantage over an interleaved queue. Select sustained throughput as total matched bytes divided by total elapsed time across all repetitions, including slow trials; median or peak trial rates are supplementary. A finite spatial control may change whole-scene edge/request counts, so retain a separate full-grid request-count sensitivity. An endpoint/concurrency gain measured on a different observation mix is conditional, not a causal increment. Choose stable throughput with tail latency, retries, CPU/RAM and writer pressure included.

For scaled-integer HLS, freeze scale/offset, rounding, nodata and reconstruction arithmetic; check integer granularity and the full valid range before casting. Preserve valid zeroes, negative values, outliers, each band mask and independent QA; never clip overflow or trade valid values for a nodata sentinel. Prove reconstruction over every valid value in the claimed accepted cohort, with per-band counts, extrema, errors and mask/QA equality. A native scale or a sampled success is not a full-cohort lossless proof. A completed local roundtrip can establish storage feasibility even when its second archive was intentionally not retained; report that distinction. Local Deflate/ZSTD savings do not establish HTTP savings, wall-time savings or lower EECU. Online integer transport needs separate matched-region, larger-block, real-concurrency and replay validation; a few sources at low concurrency do not promote it to production. S1 linear power needs its own encoding/error analysis.

Full frozen-cohort delivery, independent atom acceptance, recovery and complete-cohort HLS integer reconstruction have been exercised in the calling project. They establish their audited cohort and recipes, not archive-wide scientific qualification or universal throughput settings. Keep event lists, exact measurements, selected parameters, job IDs and route outcomes in the calling project; a route is unverified until its actual endpoint works. Do not infer production settings from a small online encoding control.

Keep logical full-grid bytes, observed valid bytes, actual HTTP response bytes and compressed stored bytes as separate quantities. If estimating whole-series HTTP from a scoped HTTP/stored ratio, first reconcile the accepted journal and state its observation-density and encoding assumptions. Do not derive time or EECU by multiplying storage compression ratios. Repairs must merge the original phase's successful transfers, elapsed time, HTTP attempts, failures and unknown costs with the repair, rather than reporting only the final successful suffix. Measure recovery hashing separately from new transfer; recover once and retain verified identities in memory without replacing the independent full-support audit.

Freeze transitively imported helpers along with the submitted entrypoint and exercise that exact offline CLI before queuing it. Reuse a completely enumerated frozen asset inventory for later pixel trials. A new cloud/QA screening pass is useful only if its source-valid denominator, threshold and measured exclusion benefit justify its cost; compute saved-pixel QA first when those pixels already exist.

## Deterministic payload rejection

`DownloadEngine` stops replaying the explicit Earth Engine `Total request size (...) must be less than or equal to ... bytes` error, since repeating the unchanged expression/grid cannot fix that limit. It retains the failure/attempt ledger. 429 and transient network failures keep bounded backoff/retry; this is not a blanket rule to suppress every 400 or authentication failure. Replan an oversized unit before a new request. Failed or rejected computation cost remains unknown unless separately reported by Monitoring.

Account for the empirically observed server mask overhead in the computation planner as well as the value dtype. Online integer encoding must compare the same source region, preserve independent QA and test the larger block shape; fewer bytes alone do not establish higher throughput.


## Download-only objectives and multi-exit trials

When the user excludes downstream local work from download cost, use total successful response-body bytes divided by the summed first-compute-HTTP-start to last-response-completion spans across matched repetitions. Report reference reads, SHA, decoding, compression and publication separately. A pre-send guard, pool wait or publisher backpressure can still lengthen that observed span; do not subtract overlapping slot-time sums from wall time. Omit repeated reference-raster reads from formal transfers by reusing the frozen recipe/source/grid and prior acceptance evidence. This does not turn pending downstream validation into a passed scientific QA claim.

Compare node A alone, node B alone and both together with identical aggregate request concurrency, writer count and source work. Reverse the assignments so each route sees the same full cohort. Preserve failed partial bodies and unreported EECU as unknown. Multiple subscriptions do not establish independent capacity or enlarge a GEE project's quota. Bind worker processes explicitly to isolated node-specific proxies: consistent-hash groups can send the same GEE destination to only one node. Keep measured operating settings and route outcomes in the calling project.
